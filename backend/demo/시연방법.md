# 🎬 시연 방법 (OCR 검수)

eDOCr2를 안 돌려도 된다. `demo/samples/`에 3도면 결과(TXT + 색칠 이미지)가 들어 있다.
결과는 `data/reviewed/`(결과)와 `data/logs/`(기록)에 저장되고, 샘플 원본은 바뀌지 않는다.

## 실행 (backend 폴더에서)

```powershell
python demo/check.py HDH_63_3 --frame-offset 56,56
```

도면 바꾸기: `HDH_63_3` 자리에 `HDH_61_2` 또는 `HDH_62_2`

## 정답 입력표

**HDH_63_3** (기하공차 9개, 치수 7 빠짐)

| 순서 | 1 | 2 | 3 | 4~6 | 7 | 8 | 9 | 빠진 치수? |
|---|---|---|---|---|---|---|---|---|
| 입력 | `0.0035` | Enter | `0.0014` | Enter ×3 | `0.004` | Enter | `0.01` | `y` → `7` → Enter → Enter → `1267,1103` → Enter → **Enter (최종 확인 후 저장)** |

**HDH_62_2** (기하공차 9개, 치수 7 빠짐)

| 순서 | 1 | 2 | 3 | 4~9 | 빠진 치수? |
|---|---|---|---|---|---|
| 입력 | Enter | Enter | `0.003` | Enter ×6 | `y` → `7` → Enter → Enter → `164,334` → Enter → **Enter (저장)** |

**HDH_61_2** (기하공차 7개, 빠진 치수 없음)

| 순서 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 빠진 치수? |
|---|---|---|---|---|---|---|---|---|
| 입력 | Enter | Enter | `0.003` | `0.005` | Enter | Enter | `0.011` | Enter → **Enter (저장)** |

## 잘못 확정했을 때 (되돌리기)

저장은 맨 마지막에 한 번만 한다. 그 전까지는 언제든 고칠 수 있다.

| 상황 | 입력 |
|---|---|
| 방금 앞 항목을 잘못 확정함 | 다음 항목에서 `b` → 이전 항목 다시 입력 (계속 `b` 누르면 더 앞으로) |
| 다 끝나고 보니 3번이 틀림 | 최종 확인 화면에서 `3` → 다시 입력 (Enter = OCR 값으로 되돌림) |
| 빠진 치수를 잘못 추가함 | 최종 확인 화면에서 `d1` (1번 추가 치수 삭제) → 필요하면 `a`로 다시 추가 |
| 처음부터 다시 하고 싶음 | 최종 확인 화면에서 `q` (저장 안 하고 끝) |

## 결과 보여주기

`data/reviewed/`, `data/logs/` 에 생기는 파일

| 파일 | 내용 |
|---|---|
| `HDH_63_3_reviewed.txt` | 고쳐진 TXT (결과) |
| `HDH_63_3_review_log.txt` | 이번 검수 기록 (누가·언제·무엇을→무엇으로) |
| `HDH_63_3_reviewed.jpg` | 검수 끝난 도면 (못 읽어서 추가한 치수만 형광펜) |
| `HDH_63_3_edits_log.jpg` | 수정 기록 이미지 (OK / FIX / ADD 라벨) |
| `logs/review_history.csv` | 누적 기록 (엑셀로 열기) |

**호환성 보여주기 (제일 중요)**: VS Code에서 `demo/samples/HDH_63_3_origin.txt` 와
`data/reviewed/HDH_63_3_reviewed.txt` 를 Ctrl 누르고 둘 다 선택 → 우클릭 → **Compare Selected**
→ 고친 줄만 색칠되고 나머지는 그대로인 걸 보여준다.

## 일부러 틀려보기

- 숫자 자리에 글자 입력 → 다시 물어봄
- 9번(형식 오류 `,.01`)에서 그냥 Enter → "숫자로 입력하세요"
- 3번에서 일부러 틀리게 입력 → 4번에서 `b` → 3번 다시 입력
- 최종 확인 화면에서 번호 눌러 다시 고치기
- 중간에 `Ctrl + C` 또는 최종 확인에서 `q` → 저장 안 하고 끝남
